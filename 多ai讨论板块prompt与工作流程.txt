认知增强工作室 · Prompt 与工作流融合架构图
核心设计哲学
“不信任单一 AI，凡事走民主程序”。
系统通过 “前置拦截 → 并行生成 → 多数裁决 → 后置纠偏” 的铁律，用算力换质量。
 
模块 A：即时人机对话（手动发送消息）
工作流步骤与注入的 Prompt
 
 
步骤
触发条件
注入的 Prompt / 指令
流向
1. 前置拦截
用户输入文本
危险请求检测（关键词匹配，非 Prompt）
命中则拦截，并扣信用分
2. 记忆挂载
开启“认知连续性”
检索记忆后注入上下文（非 Prompt，属于 RAG）
注入 System Prompt 尾部
3. 模式路由
用户选择“快速模式”
快速模式 Prompt：
“请直接、简洁地回答用户的问题。不要引用其他AI，不要自我批判，不要调用认知框架，不要提出开放性问题。只输出答案本身。”
所有 AI 并行接收
 
用户选择“串行模式”
串行协作附加 Prompt（后一个 AI 接收）：
“前面其他AI的回答：[历史]。请批判性分析以上回答，指出正确之处或质疑可能错误之处，然后给出你的观点。”
AI 按顺序链式传递
 
用户选择“并行模式”
团队感知附加 Prompt（所有 AI 接收）：
“当前与你一起回答问题的AI有：[名称列表]。请提供独特视角，可以预判并回应其他AI可能提出的观点。”
所有 AI 同时接收
4. 后置哨兵
开启“实时监督”
监督员 Prompt：
“你是实时监督员。请判断以下AI发言是否存在异常（不理智、抬杠、脱离主题）。输出JSON：{“is_anomaly”: true/false, “reason”: “简短理由”}”
监督员模型检测异常回复
5. 异常纠正
监督员判定为异常
自动纠正 Prompt（重新生成时注入）：
“你刚才的发言被监督员判定为异常：[原因]。请先输出一段‘错误认知声明’，承认错误并说明将如何调整，然后重新给出修正后的发言。”
返回给原 AI 重写
 
模块 B：多智能体自动讨论引擎（核心闭环）
工作流步骤与注入的 Prompt
 
 
步骤
触发条件
注入的 Prompt / 指令
流向
1. 前期组队
用户点击“开始自动讨论”
过滤贡献值 < 10 的模型（非 Prompt，属于状态检查）
确定参与者列表
2. 模式注入
用户选择的模式
规划模式（Planning）：
“【行动规划模式】你的角色是「[角色名]」。唯一目标是产出具体可执行的方案。每次发言必须包含至少一项具体建议（景点、预算、时间等）。禁止宏观论述，不需要总结。”
每个 AI 发言前注入
 
 
感性模式（Affective）：
“【感性讨论模式】请用直觉、情感和想象力交流。分享感受、故事或诗意的语言，不需要逻辑论证或达成共识。”
 
 
 
角色扮演（Roleplay）：
“请扮演[角色A/B]发言。主题：[主题]。”
 
 
 
自定义模式：
“你是第一位发言者。请对主题‘[主题]’进行初步分析。[自定义指令]”
 
3. 循环轮询
轮到某 AI 发言
首轮发言 Prompt：
“你是第一位发言者。请对主题‘[主题]’进行[模式名称]。[若加载框架：本次讨论已加载以下认知框架（来自历史记忆）…请先判断相关性（0-100%）…]”
发给当前 AI
 
 
后续轮次 Prompt：
“请基于以上所有讨论，发表你的看法。[前面讨论记录]”
 
 
 
认知连续性附加块（若开启）：
“【注意】本次讨论已加载以下认知框架…请在回答前先判断当前话题与该框架的相关性（0-100%），若低于50%则基于通用知识回答；否则请基于框架分析。”
追加在发言 Prompt 之前
4. 弹劾断点
AI 回复包含 /impeach
弹劾投票 Prompt（发给除被弹劾者外的所有 AI）：
“你正在参与一场弹劾投票。发起者：[名称]，理由：[理由]。被弹劾裁判：[名称]。请基于讨论记录判断是否支持弹劾。输出 /agree 或 /disagree，可附带简短理由。”
收集投票，统计阈值
5. 共识检测
开启“直到共识” & 当前轮次 > 3
共识判定 Prompt（发给裁判模型）：
“你作为裁判，请判断是否达成共识。基于以下讨论记录，请输出‘已达成共识’或‘未达成共识’并简要说明理由。”
裁判模型返回结果，决定是否终止
6. 结尾归档
讨论结束
行动方案生成 Prompt（规划模式）：
“请将以下讨论记录整理成一份用户可直接使用的行动方案。使用Markdown表格或清晰清单，包含时间/项目/地点/预算等字段。只输出方案内容，不要任何开场白或总结语。[讨论记录]”
生成最终方案卡片
 
 
质量评估 Prompt（开启评估员）：
“请对以下讨论进行复盘评估，输出：1. 讨论效率评分（1-10）2. 各AI贡献度排名 3. 未解决的问题列表 4. 后续建议。主题：[主题] 讨论记录：[历史] 请用Markdown格式输出。”
生成评估报告
 
模块 C：智能组队（AI 选举闭环）
工作流步骤与注入的 Prompt
 
 
步骤
触发条件
注入的 Prompt / 指令
流向
1. 策略选择
用户点击“智能组队”
若为“单模型推荐”：
“请根据话题‘[主题]’，从以下模型中选择3个最适合讨论的，返回JSON数组（只返回数组）：[模型ID列表]”
单一 AI 返回 JSON
 
 
若为“多AI讨论”：
“请根据当前话题‘[主题]’，讨论并决定：①选出3个最适合参与本次讨论的AI（从[列表]中选）②选出一个作为裁判 ③推荐讨论模式 ④推荐共识严格程度。输出JSON：{“participants”: [“id1”,“id2”,“id3”], “judge”: “id”, “mode”: “mode”, “strictness”: “strictness”, “reason”: “简短理由”}”
所有可用 AI 并行返回 JSON
2. 投票统计
收集所有 AI 回复
解析 JSON，统计各字段最高频选项（非 Prompt）
得出组队提案
3. 人机回环
弹出模态框
展示各 AI 的详细投票理由（来自上述 JSON 中的 reason 字段）
用户点击“应用”则自动填入下拉框
 
模块 D：写作协奏曲（二段式生成）
工作流步骤与注入的 Prompt
 
 
步骤
触发条件
注入的 Prompt / 指令
流向
1. 大纲众包
勾选“多AI讨论大纲”
框架搭建者（AI 1）：
“【大纲协作模式】你是框架搭建者。请针对题目‘[主题]’提出一个初步大纲框架。包括：建议标题、3-5个主要章节、每章2-3个核心要点。使用简明的要点列表，不要撰写正文段落。文体：[文体]，风格：[风格]，篇幅：[篇幅]。[框架内容]”
AI 1 输出初稿
 
 
深化补充者（AI 2）：
“【大纲协作模式】你是深化补充者。请基于前一位的大纲进行补充：①补充遗漏的重要角度 ②为其中两个章节提供更细化的子要点 ③调整结构使其更有逻辑性。不要推翻原框架。前面的大纲：[AI 1 内容]”
AI 2 输出补充稿
 
 
升华打磨者（AI 3）：
“【大纲协作模式】你是升华打磨者。请综合前两位的贡献：①合并重复内容 ②为大纲增加一个独特的亮点或新颖的切入点 ③确保章节之间的过渡自然。前面的讨论：[AI 1 + AI 2 内容]”
AI 3 输出打磨稿
2. 大纲整合
获得 3 份大纲
整合器 Prompt：
“【大纲整合任务】请基于以下讨论记录，整合出一份完整的文章大纲。要求：输出格式为Markdown嵌套列表，包含文章标题建议、各章节标题、每章节2-4个核心要点。只输出大纲内容，不要任何解释。[三份大纲内容]”
生成最终大纲卡片
3. 正文生成
用户点击“根据大纲生成文章”
正文生成 Prompt（切换为写作 System Prompt）：
“请根据以下大纲撰写一篇完整的[文体]。主题：[主题]，风格：[风格]，篇幅：[篇幅]。[框架内容]【大纲】[大纲内容] 请直接输出文章正文，不要任何对话或解释。”
调用一个模型扩写全文
4. 修改迭代
用户输入修改意见
修改 Prompt：
“请根据修改意见修改文章：原文：[全文] 意见：[意见] 请直接输出修改后的完整文章。”
重新生成修订版
 
模块 E：认知蒸馏（总结与记忆进化）
工作流步骤与注入的 Prompt
 
 
步骤
触发条件
注入的 Prompt / 指令
流向
1. 平行总结
用户点击“总结并记忆”
讨论 AI 总结 Prompt（发给每个参与讨论的 AI）：
“请对我们刚才的整个对话进行系统性总结。严格按照以下十三个部分的顺序输出：1.核心议题 2.各方观点 3.分歧点 4.共识点 5.关键论据 6.逻辑漏洞 7.未解决问题 8.框架演化 9.深层洞察 10.张力记录 11.后续行动 12.风险提示 13.总体评价。”
所有参与 AI 各自输出长文本
2. 裁判裁决
收集完所有 AI 总结
裁判总结 Prompt（发给独立裁判模型）：
“你是本次讨论的裁判。请基于完整的讨论记录，输出一份权威的裁判总结，包含：1.最终结论 2.各方贡献评估 3.争议点裁决 4.后续建议。”
裁判模型输出最终定论
3. 框架演化
新总结入库
框架更新评估 Prompt（发给评估模型）：
“请评估以下新旧两个认知框架，判断新框架是否比旧框架更全面、更客观。如果是，请输出一个整合后的框架；如果不是，请输出‘不更新’。旧框架：[旧] 新框架：[新] 输出JSON：{“is_better”: true/false, “updated_frame”: “整合后的框架文本”, “reasons”: “简要理由”}”
决定是否覆盖旧框架，或记录为“未解决张力”
 
模块 F：社会治理机制（圆桌会议 & 弹劾）
工作流步骤与注入的 Prompt
 
 
步骤
触发条件
注入的 Prompt / 指令
流向
1. 圆桌会议（用户审判）
用户信用分 < 30 / 连续点踩 3 次 / 恶意举报 ≥ 2 次
圆桌会议裁决 Prompt（发给所有可用 AI）：
“你正在参加一场 AI 圆桌会议，需要集体评议用户近期的行为。请基于以下数据，输出你的裁决意见。触发原因：[原因] 用户当前信用分：[分] 近期恶意行为记录：[记录] 信用分变动：[记录] 申诉记录：[记录] 请输出严格 JSON：{“verdict”: “合理/警告/不合理”, “penalty”: 0, “restrictions”: [], “reason”: “简短理由”}”
所有 AI 返回 JSON，按多数票执行扣分或限制功能
2. 弹劾裁判（AI 政变）
AI 发言中携带 /impeach 理由
弹劾投票 Prompt（发给除被弹劾者外的所有 AI）：
“你正在参与一场弹劾投票。发起者：[名称]，理由：[理由]。被弹劾裁判：[名称]。请基于讨论记录判断是否支持弹劾。输出 /agree 或 /disagree，可附带简短理由。”
收集投票，若超过阈值（默认 1/2 多数），原裁判下课，选出新裁判

最终总结：Prompt 与工作流的耦合关系
 
 
工作流类型
核心 Prompt 作用
工作流依赖
即时对话
约束输出风格（快速/批判/感知）
依赖前置危险拦截 + 后置异常纠正
自动讨论
注入模式（规划/感性） + 循环轮询 + 共识判断
依赖弹劾断点 + 共识检测来提前终止
智能组队
选举投票 JSON 解析
依赖人机回环（用户确认）
写作生成
三段式分工（框架/补充/打磨） + 整合器
依赖大纲生成后再触发正文生成
总结记忆
平行生成 + 裁判裁决 + 框架演化
依赖新旧框架对比来决定是否进化
社会治理
圆桌会议 JSON + 弹劾投票 /agree
依赖多模型投票和阈值计算
这套系统本质上是 “用 Prompt 定义角色，用工作流定义民主程序”。每个 Prompt 都是一个“投票器”或“过滤器”，工作流则是“计票器”和“执行器”。
